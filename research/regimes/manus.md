## Compute / overage / caps
Agent credits track complexity and duration rather than a fixed task or CPU tariff. Agent-session hardware and credit burn/hour null. Both listed paid Pro levels support 20 concurrent and 20 scheduled tasks per the membership article, below the 50-concurrent reference workload. Persistent computers are **separate monthly purchases**, Ubuntu Server 24.04 LTS with a public IP; can run services outside active agent sessions. Restart needed on upgrade. Cancellation risks deleting stored data; export first. They are not a guaranteed free bundle on an expensive agent tier. [Computer billing](https://help.manus.im/en/articles/15392078-understanding-cloud-computer-plans-and-billing)
The free-access campaign waives eligible Lite/Standard usage only within daily allowances; queues/risk controls remain, Max excluded. This is promotional, not an unlimited stable entitlement. [Campaign](https://help.manus.im/en/articles/16312548-manus-free-access-campaign-rules)
## Examples / gotchas
Single developer can buy Standard persistent compute for $30/month **plus agent plan/usage as applicable**. At an assumed 730-hour month that is $0.04110/hour amortized, not an hourly offer. Fifty Advanced machines would cost $2,500/month if account quotas permit, but still only **2 CPUs each**, so they fail the standard 4/8 workload; do not double up machines and claim one equivalent worker. Agent 8,800-hour cost remains null. Snapshot/egress quotas and charges, allowed server count, credit top-up rate need confirmation. No card because agent credits cannot normalize and the separate fixed-month 2-CPU add-on does not meet reference sizing.
Higher packs reduce nominal fee/credit, not a fixed CPU tariff. All observed cards retain 20 concurrent/20 scheduled tasks. These are rendered list tiers, not third-party estimates. [Pricing](https://manus.im/pricing)
The current product documentation describes Manus 2.0; the older membership/campaign pages still name 1.6 variants. Treat their campaign waiver as scoped to those named modes, not automatically transferable to every current 2.0 capability.
